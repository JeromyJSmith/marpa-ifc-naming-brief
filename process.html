Process

The sequence is what makes the data useful

The work starts with the actual project files, not a guessed database schema. We inventory one project, extract every useful representation, compare what each format contains, then build the MARPA object model that can drive IFC, cost analysis, reports, and Vectorworks writeback.

select one project and freeze the design state
↓
connect to Vectorworks through MCP and scripting
↓
inventory layers, classes, records, sheets, worksheets, resources, plants, symbols, and site settings
↓
export every useful representation from the same state
↓
extract text, geometry, images, tables, quantities, materials, and references
↓
compare format coverage and build the MARPA naming bridge
↓
publish analysis-ready evidence, simulate pricing, and write enriched IFC forward

Why the order matters

  • Guessing table schemas before the source data is known.
  • Losing original Vectorworks naming and context.
  • Assuming IFC contains geometry or quantities that may only exist in DWG, PDF, or worksheets.
  • Building cost analysis on disconnected spreadsheet rows.
  • Creating 3D enrichment without source lineage.
  • Sending enriched geometry back to Vectorworks without proof of where each object came from.

Evidence package structure

The package keeps the source and the interpretation separate

Raw project evidence

  • VWX document metadata and MCP readback.
  • IFC 2x3, IFC4, and IFC4x3 where available.
  • DWG/DXF linework, layers, blocks, scale clues, and annotations.
  • PDF sheets, vector paths, text spans, rendered sheets, and extracted images.
  • Worksheets, schedules, reports, plant records, symbols, materials, and resource assets.
  • Budgets, estimates, catalogs, quotes, spreadsheets, and formula workbooks connected to the same project.

Normalized evidence

  • Stable source asset ids and derived artifact ids.
  • Extracted pages, tables, text spans, vector paths, images, masks, and object crops.
  • Object candidates for hardscapes, walls, planting beds, trees, materials, and schedule rows.
  • Quantity evidence: count, area, length, volume, unit, source worksheet, geometry basis, and confidence.
  • Classification candidates: MARPA object type, IFC entity, property set, cost code, material basis, and estimate group.
  • Source lineage linking every fact back to file, page, sheet, worksheet, object, export script, and parser.

The split lets each kind of evidence keep its own rules while still joining through stable source ids, project ids, object ids, geometry ids, and cost ids.

Analysis and cockpit

Then the database supports live estimating and reports

Modeling work

  • Normalize quantities, units, materials, plant names, and location factors.
  • Attach historical project costs and comparable-project context.
  • Run deterministic cost models first, then regression and uncertainty analysis where the evidence supports it.
  • Track estimate ranges, low/high values, confidence, and model diagnostics.
  • Keep formulas from MARPA workbooks visible so the report values can be explained.

Marimo cockpit

  • Project tabs load the current evidence package and analysis-ready outputs.
  • Sliders adjust markup, labor, material, vendor, risk, contingency, location, and schedule assumptions.
  • MARPA report templates populate in real time from normalized data.
  • Each scenario writes a decision record and keeps source/product versions attached.
  • The selected scenario becomes the writeback package for IFC and Vectorworks.
