# What Stakeholders Will See

Stakeholders should not need to understand every internal tool. They should see a clearer process and better outputs.

## A Clearer Project Story

The system can show how a design object moves through the process:

1. It starts in Vectorworks.
2. It appears in exports, worksheets, images, schedules, or IFC.
3. It receives a stable MARPA identity.
4. It gets quantity, cost, asset, and classification context.
5. It appears in review surfaces and reports.
6. It can support approved downstream outputs.

## Better Review Surfaces

Stakeholders can expect:

- project summaries;
- evidence-backed cost views;
- BIM/IFC validation summaries;
- plant and hardscape asset views;
- client-facing 3D scenes;
- georeferenced site context;
- review packets that explain the source of numbers.

## Better Financial Conversations

The financial lane gives the team a path toward:

- baseline cost intelligence;
- project-to-project comparison;
- early estimate ranges;
- pricing assumptions tied to evidence;
- future predictive models.

The first goal is not magic prediction. The first goal is reliable data that can support prediction later.

## Better Client-Facing Presentation

The 3D lane gives the system a way to make the design visible:

- georeferenced scenes;
- cinematic review;
- real assets;
- context-aware layers;
- proof that connects visual presentation back to technical and cost evidence.

## Better Internal Control

The team will also see better internal control:

- agent work tracked by receipts;
- source registries for external tools;
- CI and hook checks before work lands;
- clear lane ownership;
- fewer hidden assumptions.

This reduces rework because decisions become visible earlier.
