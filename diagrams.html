Large-format data pipeline maps

These diagrams are intentionally long and vertical. They are meant to be read on screen during a conversation, not squeezed into a single horizontal technical chart.

Diagram 1

Pipeline flow from Vectorworks to useful project intelligence

The system starts with one design state, gathers every useful export, then builds one evidence package that can support IFC, cost analysis, reporting, and Vectorworks writeback.

1. Same project / same design state

Open the current Vectorworks project and tie the whole harvest to that exact file state, active export settings, units, layers, sheets, and project context.

↓

2. Vectorworks MCP and scripting harvest

Read document settings, layers, classes, records, worksheets, resources, symbols, plant records, and export capabilities directly from Vectorworks.

↓

PDF / document exports

Sheets, annotations, text, page geometry, images, plans, and human-facing report content.

DWG / DXF / image exports

Hardscape linework, design-layer geometry, sheet images, rendered views, scale, and visual grouping.

IFC / worksheet exports

Entity candidates, property coverage, schedules, quantities, cost rows, and formula evidence.

↓

3. Normalize into one source evidence package

Every extracted fact keeps its source file, page, layer, worksheet, object name, export settings, and extraction receipt.

↓

4. Build MARPA naming and classification bridge

Original Vectorworks names stay preserved. MARPA adds stable object identity, canonical category, quantity basis, IFC mapping, and cost classification.

↓

IFC enrichment

Attach entities, property sets, quantities, source lineage, and MARPA object identity.

Predictive pricing

Use object-level quantities, workbook formulas, historical costs, market factors, and estimate ranges.

Review surface

Show live Marimo reports, dashboards, 3D review, and scenario sliders for project decisions.

↓

5. Write useful information back into Vectorworks

Enriched IFC and receipts make Vectorworks more useful on the next project: better objects, better schedules, better search, and better cost analysis.

Diagram 2

Evidence package structure

The evidence package is the thing we build before final database schemas. It says what was extracted, where it came from, what it might mean, and what still needs comparison.

Project and export identity

MarpaProject

Project code, job number, client/project name, active Vectorworks file, project state, and export run identity.

ExportArtifact

Each PDF, IFC, DWG/DXF, worksheet, image, and report gets a source path, file hash, export settings, timestamp, and method.

↓

Document and page extraction

ExtractedPage

Sheet number, page size, render, scale clues, sheet title, and page-level source references.

PdfTextSpan

Labels, dimensions, notes, callouts, schedules, and any text that can help classify objects or quantities.

ExtractedImageAsset

Plan images, plant symbols, rendered sheet views, background-removed assets, and visual segmentation candidates.

↓

Vectorworks and geometry evidence

VectorworksObjectIdentity

Layer, class, object name, record format, worksheet, resource name, symbol reference, plant record, and document context.

PdfVectorPath

Vector linework, possible object boundaries, text-relative geometry, sheet-space coordinates, and plan symbols.

GeometryCandidate

Hardscape, wall, planting bed, tree, material area, or other spatial object candidate with source confidence.

↓

Quantity, classification, and cost meaning

QuantityEvidence

Count, area, length, volume, unit, worksheet source, geometry source, and measurement basis.

ClassificationCandidate

MARPA category, IFC entity candidate, property set mapping, cost code, material basis, and estimate group.

SourceLineage

Which file, page, worksheet, object, export, script, or model produced each fact, so the pipeline can explain itself later.

Diagram 3

Parallel work lanes that converge into the MARPA model

These lanes can move at the same time. They do not become final schemas until the source evidence is understood and the naming bridge is clear.

1

Project control-file shortlist

Separate current project VWX files from backups, libraries, templates, samples, and platform/tooling files.

2

Vectorworks MCP harvest

Inspect the active document: layers, classes, records, worksheets, resources, symbols, plants, units, export settings, and document preferences.

3

Export matrix

Export PDF, DWG/DXF, IFC variants, worksheets, reports, design-layer images, sheet images, and resource evidence from the same design state.

4

Document and image separation

Use document extraction to split pages into text, tables, vector paths, figures, images, layout blocks, and background-removed visual assets.

5

Workbook and formula extraction

Preserve XLSX formulas, schedules, quantities, rates, markup logic, margin assumptions, and report-template fields as source evidence.

6

IFC version comparison

Compare IFC 2x3, IFC4, and IFC4x3 exports to see which entities, properties, geometry, and quantities actually survive each path.

↓

Convergence point: MARPA naming and Pydantic model

All lanes feed one object identity model: Vectorworks source identity, MARPA canonical name, geometry evidence, quantity evidence, IFC mapping, cost classification, and source lineage.

↓

Normalized database

Only after evidence and naming are understood.

Predictive pricing

Object-level costs, ranges, risk, and report values.

Vectorworks writeback

Enriched IFC and better project objects.
