Pipeline diagrams

The design is the data pipeline

These diagrams show how we move from one Vectorworks design state into source evidence packages, MARPA naming, IFC enrichment, cost analysis, review, and Vectorworks writeback.

End-to-end architecture

flowchart TB
  VW["Vectorworks project file\nVWX + active design state"] --> MCP["MCP / Vectorworks scripting\ninspect + export"]
  MCP --> EXPORTS["Export package\nPDF • DWG/DXF • IFC variants • worksheets • images"]
  EXPORTS --> DOCS["Document separation\ntext • tables • figures • layout • images"]
  EXPORTS --> GEOM["Geometry extraction\n2D linework • IFC entities • vector paths"]
  EXPORTS --> SHEETS["Worksheet/formula evidence\nquantities • rates • categories"]
  DOCS --> PACKAGE["Normalized evidence package\nJSON + files + receipts"]
  GEOM --> PACKAGE
  SHEETS --> PACKAGE
  PACKAGE --> NAME["MARPA naming bridge\nstable object identity"]
  NAME --> IFC["IFC enrichment\nentities • property sets • quantities"]
  NAME --> COST["Cost model\ncodes • quantities • pricing • risk"]
  IFC --> REVIEW["Marimo / dashboard review\ninspect • adjust • compare"]
  COST --> REVIEW
  REVIEW --> WRITEBACK["Vectorworks writeback\nenriched IFC + receipts"]
  WRITEBACK --> VW
Evidence package

What one extracted project package contains

The package keeps the original exports and adds normalized objects that describe pages, text, images, Vectorworks identity, quantities, classifications, and source lineage.

Evidence package structure

flowchart TB
  ROOT["ExtractedSourcePackage"] --> PROJECT["MarpaProject\nproject code • job number"]
  ROOT --> ARTIFACT["ExportArtifact\nfile hash • export settings • source path"]
  ROOT --> PAGE["ExtractedPage\nsheet number • scale • page image"]
  PAGE --> TEXT["PdfTextSpan\nlabels • notes • dimensions"]
  PAGE --> PATHS["PdfVectorPath\nlinework • symbols • possible geometry"]
  PAGE --> IMG["ExtractedImageAsset\nrendered views • plant images • sheet images"]
  ROOT --> VWOBJ["VectorworksObjectIdentity\nlayer • class • record • resource"]
  ROOT --> CANDIDATE["ObjectCandidate\nhardscape • plant • wall • material"]
  CANDIDATE --> QTY["QuantityEvidence\ncount • area • length • volume • unit"]
  CANDIDATE --> CLASS["ClassificationCandidate\nCSI • MARPA category • IFC entity"]
  CANDIDATE --> LINEAGE["SourceLineage\nwhich file/page/tool produced the fact"]
Naming bridge

How names become useful downstream

Vectorworks names stay preserved, MARPA adds stable object identity, and that identity carries IFC, quantity, and cost meaning into the rest of the workflow.

Naming bridge

flowchart TB
  A["Vectorworks names\nlayers • classes • records • worksheets"] --> B["MARPA canonical object model\nstable object id"]
  B --> C["IFC mapping\nentity • property set • classification"]
  B --> D["Cost / quantity taxonomy\nunit • rate • takeoff basis"]
  C --> E["Enriched IFC\nportable BIM data"]
  D --> F["Estimate model\ncost ranges • risk • scenarios"]
  E --> G["Vectorworks import\nbetter BIM objects"]
  F --> H["MARPA review\npricing and scope decisions"]
