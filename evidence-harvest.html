Evidence harvest

We do not assume one export contains everything

Vectorworks is the source environment, but the truth is fragmented across export modes. The harvest step collects all useful representations, then compares them before naming or loading anything.

Source Likely useful data Why it matters
VWX document Layers, classes, records, worksheets, resources, symbols, plant objects, document settings Best source for native design intent and naming.
PDF sheets Text labels, sheet layout, annotations, page geometry, raster images, possible vector paths Captures what humans actually review and price from.
DWG / DXF Hardscape geometry, annotation geometry, layers, linework, blocks, scale context Often contains 2D geometry missing from IFC exports.
IFC 2x3 / IFC4 / IFC4x3 Entities, property sets, spatial hierarchy, object relationships, partial geometry Target format for BIM exchange and enrichment.
Worksheets / reports Counts, areas, plant schedules, material lists, dimensions, estimate references Often the cleanest quantity and schedule evidence.
Rendered images Sheet views, design-layer views, plant symbols, visual grouping, image assets Useful for segmentation, review, and 3D asset generation.

Candidate tools

  • MinerU for document layout, images, tables, Markdown, and JSON.
  • PyMuPDF and pdfplumber for comparison and extraction checks.
  • OCR only when the document is scanned or text extraction is broken.
  • Image segmentation later, after source identity is captured.
