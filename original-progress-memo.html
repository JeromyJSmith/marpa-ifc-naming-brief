Progress memo for MARPA review

MARPA IFC Naming Bridge

Vectorworks is the source environment, but the useful project truth is fragmented across export modes.

PDF sheets, DWG/DXF geometry, IFC files, worksheets, schedules, plant records, symbols, rendered images, and design-layer images each carry a different part of the story.

The bridge keeps MARPA's source naming intact, then adds one stable object identity that can travel through IFC, quantity takeoff, cost analysis, 3D enrichment, and writeback.

same project / same design state
↓
export every useful evidence format
↓
parse each export into a normalized evidence package
↓
compare what each format contains and misses
↓
build MARPA naming / classification bridge
↓
attach IFC entities, property sets, quantities, and cost references

Why do this?

  • One stable name for each project object.
  • Original Vectorworks layers, classes, records, and worksheet names stay preserved.
  • Missing geometry, quantities, and source evidence become visible.
  • Cost analysis can attach to real design objects instead of loose rows.
  • IFC exports become easier to validate and enrich.
